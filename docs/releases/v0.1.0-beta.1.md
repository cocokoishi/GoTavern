# GoTavern Beta 1 (v0.1.0-beta.1)

GoTavern is SillyTavern's server, rewritten in Go: one binary, the unmodified upstream frontend, the same
`config.yaml`, the same `data/` folder, no conversion and no private database. Beta 1 is the release where the
project stops being a carefully qualified alpha and starts being a backend a user can run for months and report
edge cases against with enough diagnostics to act on them.

**Channel:** `v0.1.0-beta.1` is published on the **prerelease** channel. GitHub marks it a pre-release,
`releases/latest` keeps serving the stable `v0.1.0-alpha.9` release, a bare `install.sh` / `install.ps1` installs
that stable release, and Docker `:latest` stays on the stable image. Installing the Beta is an explicit decision:
`install.sh --version v0.1.0-beta.1`, `install.ps1 -Version v0.1.0-beta.1`, or
`docker pull ghcr.io/cocokoishi/gotavern:v0.1.0-beta.1`. The rule lives in one script,
`scripts/classify-version-tag.sh`, shared by the release workflow, the Docker workflow and both installers.

## Why Beta

The alpha series ended with `v0.1.0-alpha.9`, which graduated to the stable channel. Beta 1 is not
"alpha.9 plus features": it is the release where every known open investigation was either resolved with an
oracle-backed verdict or re-classified with its exact missing evidence, and where the release process itself
became a machine gate instead of a remembered checklist. The number of new features is deliberately small; the
amount of behaviour that is now measured, reproducible and diagnosable is much larger.

## Major changes

### Resumed sessions after a restart: resolved, and it was the harness

The alpha.9 record carried one OPEN assertion: after a server restart, the resumed turn's captured request was a
single-system-message request that did not carry the restored history. Beta 1 resolves it with the pinned oracle
rather than an assumption:

- **Root cause (measured):** the whole-session probe selected "the resumed turn" as *the last chat-completion
  request it happened to see* (`completions().at(-1)`), and the comparator did the same. The recorded shape is
  exactly what the frontend's own quiet `generateRaw` produces (one system message, posted to
  `/api/backends/chat-completions/generate`); any later helper or quiet completion became "the resumed turn".
- **The preset hypothesis is disproven** for the committed derivation of that user preset: the runtime prompt
  order has `chatHistory` present and enabled, so both subjects legitimately send history.
- **The fix:** the resumed request is now attributed by the provider peer's ordinal armed immediately before the
  click, later completions are recorded separately, and a helper-completion injection reproduces the old failure
  deterministically. The default journey still *requires* the restored-history markers; a journey whose preset
  prompt order omits chat history is classified as a preset property, must still be **byte-identical** between
  GoTavern and pinned, and cannot pass silently.
- **Evidence:** the resumed send's request is 17,222 bytes / 12 messages / `sha256 770629b7…` and is
  byte-identical on both subjects; the injected quiet completion (199 bytes, one system message) is separately
  recorded and also byte-identical. A file-copy mutation restoring the old `.at(-1)` selection turns the named
  guards `resumed-request-attributed-to-the-send` and `restart-turn-carried-the-restored-history` red; restoring
  the probe returns match 47/47, teeth 18/18. Full record: `docs/persistence-resume.md`.
- **No Go change was needed:** the product was correct; the measurement was not.

### The Q21 hand-back flake is gone, and the reason is recorded

Alpha.9's full browser run had every leg green except `Judge the hand-back`, which was called an occasional
pinned-frontend persistence flake. Beta 1 does not ship known-occasionally-red:

- **Root cause:** a harness race, not a product difference. The pinned leg's "the send's reply landed" wait matched
  a message whose text was already present in the GoTavern-handback tree, so the CONTINUE click arrived while the
  send was still streaming, was refused by the frontend's own send-in-progress guard, and the send's later reply
  was misread as a continuation.
- **Fix:** nine named conditions with the wait and observation recorded in the report, per-subject reply tags,
  positional persistence (an assistant turn must appear *after* the send's user turn), a CONTINUE press that waits
  for the frontend's own guard inputs and reads acceptance synchronously (a refused press fails immediately with
  `continue-press-not-accepted`), and condition-based waits instead of sleeps. No timeout was widened and no
  assertion was weakened; the judge still refuses `match` on an empty report.
- **Proof:** the hand-back leg ran **20/20 green** in one repeated-stability campaign on an unchanged commit, with
  `continueRequests=1` in every iteration and all nine conditions holding; the slowest condition wait was 2.5 s
  against a 60 s bound. Record: `docs/browser-stability.md`.

### Long-lived data, not one afternoon of data

A new deterministic synthetic corpus (`tools/build-longlived-corpus.mjs`, no private data, fixed seed,
byte-identical rebuilds) is qualified at three sizes: **small** (69 files, 3.3 MB), **medium** (176 files, 49 MB,
30,264 messages) and **large** (250 files, 111 MB, 62,424 messages; nightly). It covers multiple characters with
CJK/emoji/unusual filenames, long chats with swipes/edits/branches, groups, multiple world books, the committed
complex-preset derivation, themes/backgrounds/personas/assets/Quick Replies, legacy settings keys and
stale-but-valid legacy data. The browser journey over a corpus copy resumes an existing long chat, sends, swipes,
switches preset/world/temperature, switches characters, reloads twice, saves, restarts the server on the same
tree, resumes and continues -- on both subjects -- and compares browser state, provider bytes and on-disk state
(43 matched checks, 0 mismatches, 3 recorded decided exclusions). Workflow: `GoTavern long-lived corpus
qualification`. Design and normalisation table: `docs/longlived-corpus.md`.

### Upgrades are qualified against the real published alpha.9

The release qualification downloads the **published** `v0.1.0-alpha.9` linux-amd64 archive, verifies it against the
published `checksums.txt`, installs it through the real installer, seeds the generated corpus, boots it, updates the
same tree to Beta 1 through the same installer, continues the same chat (save, restart, read-back), restores the
pre-upgrade backup and boots alpha.9 over it again. It also exercises a fresh Beta 1 install over the corpus and a
SillyTavern-data-copy drop-in, and classifies every file Beta 1 adds, changes or removes on those paths -- so "no
undocumented manual migration" is a measured statement, not a hope.

### Surface coverage is derived from the oracle and gated

`docs/surface-coverage.md` is now computed from the pinned frontend's own URL builders, the pinned server's route
registrations and its redirect aliases, reconciled against the Go registrations: **573 frontend surfaces, 384 Go
registrations, 0 unknown**, every surface classified implemented / intentionally-passthrough / not-applicable /
unsupported-with-reason. A drift gate fails CI when a new frontend request shape or a new Go route appears without
a classification, and a stale exception is itself a failure. Two genuine surface gaps were found by the gate and
are recorded rather than smoothed over: 37 of the pinned 50 legacy redirect aliases are not registered (the pinned
frontend builds none of them; legacy bookmarks only, P2), and `POST /api/tokenizers/remote/textgenerationwebui/encode`
is absent while its inventory row claimed a replay (P2; the matrix now states the contradiction).

### Data safety

Three real write-path defects were found by audit and fuzzing, fixed, and each has a failure-injection test and a
mutation that turns it red:

1. **Character rename** copied `chats/<old>` with a direct recursive copy then deleted the original. An
   interruption left a partial destination; a retry saw the destination existed, skipped the copy, and deleted the
   complete history. The copy is now staged and published with one rename (destination absent or complete).
2. **A 0-byte or whitespace-only `config.yaml`** -- exactly what a crash or a full disk leaves behind -- made boot
   fail (`yaml: cannot encode node with unknown kind 0`). Pinned repairs it to the defaults; GoTavern now does
   the same, with the repaired bytes pinned to the embedded defaults and an idempotent second boot. This was found
   by the first seed of a new fuzz target.
3. **`/api/images/upload`** truncated the existing image before writing, so a full disk or a killed process
   destroyed the previous image. It now writes atomically.

Sensitive writes now have injected disk-full, rename-impossible, killed-process, torn-read and concurrent-writer
tests (chat save, settings save, world-info edit, preset save, image overwrite). Eight fuzz targets with seed
corpora cover config, settings JSON, ordered-JSON, PNG card text, YAML, avatar crops, filename sanitization and
pinned path containment; one inherited pinned behaviour (trim-then-truncate can leave a trailing dot/space after a
255-byte truncation) is pinned as parity rather than silently "fixed". Record: `docs/data-safety.md`.

### Basic Auth: original feature, default off, now pinned in both directions

A user asked whether the password prompt is a GoTavern invention. It is a SillyTavern feature
(`config.yaml: basicAuthMode`, default `false`), and pinned gates the middleware on **`listen && basicAuthMode`**.
GoTavern reproduces exactly that conjunction. The ON direction was already compared against recorded pinned
responses; Beta 1 adds the previously untested OFF direction as an executed regression: a default configuration is
served anonymously, and `basicAuthMode: true` with `listen: false` is also served anonymously. Removing the
`listen &&` half turns that test red.

### Security baseline: off an end-of-life toolchain, and zero reachable advisories

The hardening audit found that the project was building its releases with an end-of-life Go toolchain (the
`go.mod` directive and the Docker base image said Go 1.23, which is out of support) and that every module fix was
blocked on a newer language version. Beta 1 moves the build to **Go 1.27.3** (release builds, CI and the Docker
image all follow `go.mod`), and upgrades `golang.org/x/image`, `golang.org/x/text`, `golang.org/x/sys` and
`golang.org/x/crypto` to patched releases. `govulncheck` (v1.9.0, DB 2026-10-27) went from **15 reachable
vulnerabilities** to **0** - "No vulnerabilities found". One advisory remains in a required module
(`x/crypto/openpgp`, not imported; only `scrypt`/`sha3` are used) and it has no fixed version, so it is recorded
as a non-reachable residual rather than hidden.

The toolchain move also surfaced a pre-existing Windows-only race: the account-record **read** path did not retry
the transient sharing violation that its atomic rename already retried, so an authenticated request could fail
while a record was being replaced. It is fixed with the same bounded retry on the read side (a no-op off Windows)
and covered by a 20-iteration concurrency run. Record: `docs/data-safety.md` sections 7.1, 8.2 and 9.

### The packaged drop-in gate now proves both directions

AGENTS.md 38 asks for the real migration path in the *packaged* gate: a user's tree, the shipped archive, and then
the tree handed back to the original pinned server. The hand-back was previously only a browser-differential
experiment. `GoTavern drop-in qualification`'s `dropin-current-head` now extracts the same packaged archive it
tests, hands that tree back to pinned Node over the same data root, and gates on the hand-back judge: run
**41205962399** reports `hand-back verdict: match`, GoTavern 6/6 and pinned 17/17 rows including `pinnedContinued`.
Its first execution (**41205692600**) went red for a real harness defect (`GOTAVERN_BINARY` was command-scoped and
the judge refused the claim as `unreached` instead of passing a partial), which is the gate's teeth observed rather
than asserted.


### Release governance: the checklist's "same SHA" line is now a program

- **Same-SHA required gates.** `docs/release-manifest.json` names the required workflows; before
  `gh release create`, `scripts/verify-release-gates.mjs` asks the Actions API for each one's runs whose
  `head_sha` is the tag's target commit and refuses a missing, failed, cancelled, in-progress or different-SHA run.
  The published body carries the resulting run-id table, generated at publish time, because a note cannot contain
  ids of runs that had not happened when the commit was written.
- **Release-body validation.** Drafting words, angle-bracket placeholders, fabricated short run ids, degenerate
  example checksums, digests that match no released asset, wrong-release tag tokens and stub bodies are refused on
  **both** channels. A dispatch dry run validates the candidate's notes before the tag.
- **Generated-facts lifecycle.** Creating a tag makes the committed documentation facts stale on the tagged
  commit. A post-release job regenerates them on `main`, commits with an explicit file list, pushes, and dispatches
  CI at that commit, so a release no longer leaves `main` red until someone remembers a manual step.

### Installers

- **Windows PowerShell 5.1 download stall (fixed, measured).** The ~60 MB windows archive downloaded in 2.3 s with
  `$ProgressPreference='SilentlyContinue'` and wrote **zero bytes in over five minutes** with the default progress
  rendering under Windows PowerShell 5.1 -- the default shell on Windows 10/11. The installer now sets the
  preference before its first download; the same install completes in 13.9 s locally and 3.9 s in CI.
- **The published Windows installer is executed.** A new Windows job runs the checkout's
  `install.ps1 -Version v0.1.0-beta.1` under Windows PowerShell 5.1 over real TLS, verifies the published checksum, boots
  the installed `gotavern.exe`, requires `/version` and requires **real tokenizer ids** from `src/tokenizers`
  (the fallback answers `ids:[]`), and asserts the channel direction.
- **Prerelease candidates can be rehearsed.** Before Beta 1 the prepublish qualification refused a prerelease, so
  a Beta tag could not even be dry-run. It now qualifies the tag-addressed installer forms against the mirror and
  requires **both bare installers to be refused**, proving "a prerelease never becomes `releases/latest`" before
  the tag exists.

## Compatibility

Measured against pinned SillyTavern `1.19.0` (`06bde939fb1e9c4c8d8641d810f0a916b5bce127`). The capability matrix is
`PASS 3 / PARTIAL 18 / FAIL 0 / NOT_APPLICABLE 1`; the remaining partials are `P0 0 / P1 8 / P2 10`, each with a
recorded justification in `docs/gap-sweep.md`. No PARTIAL was promoted without an executed test and no severity was
lowered to improve the numbers.

What changed from alpha.9:

- **Resolved:** the resumed-session OPEN item (harness measurement defect, above); the Q21 hand-back flake
  (harness race, above).
- **New evidence on existing rows:** surface coverage (all 573 surfaces classified; drift-gated), the long-lived
  corpus (fresh install, long-lived journey, restart, upgrade, drop-in), the published alpha.9 -> Beta upgrade, the
  published Windows installer, and the same-SHA release evidence.
- **Two newly recorded P2 surface gaps** (legacy redirect aliases; the remote text-generation-webui tokenizer
  route), found by the new gate and visible to users in the matrix rather than discovered later as a surprise.
- **Still justified P1:** CharX/BYAF/RisuAI card imports remain unimplemented (the pinned error shape is returned,
  no data hazard); group chats have route/metadata parity but no multi-character provider-order differential;
  preset features outside the measured keep/drop contract (instruct/context templates, secondary world-info keys,
  recursion/probability/outlets) are unmeasured; a real provider through a real proxy is exercised by the user, not
  by the default suite; every remote embedding source answers an honest unimplemented status; the 酒馆助手 render
  path and persisted-variable behaviour remain partially unproven.

## Persistence and upgrades

The on-disk format is unchanged: it is SillyTavern's own. Beta 1 upgrades write only files the pinned server also
writes, sensitive writes are atomic, and the published-upgrade qualification proves an existing alpha.9 tree --
config, chats, characters, presets, world books, assets, settings with unknown keys -- survives the update and
continues to be usable, in both directions (rollback to the pre-update backup also boots). No migration step is
required or documented, because none is performed.

## Installation

**Linux / macOS**

```sh
mkdir GoTavern && cd GoTavern
curl -fsSL https://raw.githubusercontent.com/cocokoishi/GoTavern/main/install.sh | sh
# Beta explicitly:
# sh install.sh --version v0.1.0-beta.1
./start.sh
```

**Windows (PowerShell)**

```powershell
mkdir GoTavern; cd GoTavern
irm https://raw.githubusercontent.com/cocokoishi/GoTavern/main/install.ps1 -OutFile install.ps1
.\install.ps1            # or: .\install.ps1 -Version v0.1.0-beta.1
.\Start.cmd
```

**Docker**

```sh
docker pull ghcr.io/cocokoishi/gotavern:v0.1.0-beta.1
```

**Manual:** download the canonical archive for your platform from this release and verify it against
`checksums.txt`. The release ships six archives: linux amd64/arm64, darwin amd64/arm64, windows amd64/arm64.
Runtime-qualified in CI: linux/amd64 (archive boot, installer, drop-in, long-lived corpus) and windows/amd64
(installer over TLS under Windows PowerShell 5.1, installed binary boot, tokenizer routes). The other four are
built and structurally inspected, but this project has no runner of those architectures and does not claim they
were executed.

## Docker

`ghcr.io/cocokoishi/gotavern:v0.1.0-beta.1` is the Beta image; `:latest` is NOT moved by a prerelease. Mutable
state (`config.yaml`, `data/`, `extensions/`, `certs/`) is never baked into the image and survives container
replacement when mounted; the image does not carry a toolchain, build cache or credentials.

## Qualification

This release is published only because the required workflows were green **at the tag's target commit**, and the
release body appends the machine-generated table naming each workflow and run id (the same table
`scripts/verify-release-gates.mjs` gates publication on). The gates are:

- `GoTavern CI` -- formatting, generated facts, compatibility matrix, surface drift, release classifier table,
  release-governance teeth, the Go suite, `go vet`, race, build, browser evidence and the full oracle sweep.
- `GoTavern whole-session differential` -- one session lineage per subject, restart and resumed turn, 12 legs, 3
  comparators, 3 teeth proofs.
- `GoTavern world-info slot ordering`, `GoTavern drop-in qualification`, `Browser differential` (mode all, plus a
  20-iteration hand-back stability campaign), `GoTavern long-lived corpus qualification` (medium),
  `GoTavern release qualification` (including the published-alpha.9 upgrade), `GoTavern smoke metrics`, and the
  `GoTavern Docker image` build/verify.
- After publication: `GoTavern published-release install smoke` pulls the **public** artifacts back over TLS and
  re-verifies install, boot and tokenizer behaviour on Linux and Windows.

## Known limitations

These are recorded limitations, not silent gaps. Each is in the compatibility matrix with its evidence.

- Arbitrary Node.js server plugins are the one explicit ecosystem exclusion (not emulated, not faked), and local
  in-process ONNX ML (captioning/classification/speech/local embeddings) is a decided boundary: it would require
  an ONNX runtime and break the single-binary `CGO_ENABLED=0` distribution.
- Every **remote** embedding provider source answers an honest unimplemented status; vector storage works with
  local/koboldcpp or caller-supplied vectors.
- CharX, BYAF and RisuAI card imports are not implemented; the pinned error shape is returned and no stored data is
  touched.
- Group chats have route/metadata parity but no multi-character prompt-order differential.
- Preset features outside the measured contract (instruct/context templates, secondary world-info keys,
  recursion/probability/outlets, group-chat presets) are unmeasured.
- A real third-party provider through a real proxy is exercised by users, not by the default suite (the provider
  differential uses a controlled recording peer); credential-gated live canaries exist but are not a gate.
- 酒馆助手 / JS-Slash-Runner: the iframe, bridge, generation, variables and preset interactions are proven; its own
  UI and any behaviour implemented purely inside the iframe are not.
- Jimp byte-equal image re-encoding is not claimed; the observable transformation (dimensions, PNG output,
  cover-not-stretch, MIME) is.
- Multi-user concurrent writes to one world/preset tree are not gated; per-user isolation is asserted per route.
- 37 pinned legacy redirect aliases are unregistered (the pinned frontend builds none of them); the remote
  text-generation-webui tokenizer route is absent while its inventory row claimed a replay.
- The four non-x86/darwin archives are built and inspected, never executed.
- Inherited upstream weaknesses are reproduced rather than silently fixed (for example content-import host
  matching uses upstream's substring test), because "safer but different" breaks drop-in parity as badly as worse.

## Breaking changes

None known. `config.yaml` keys, CLI, ports, directory layout, installer syntax, Docker volume semantics and API
response shapes are unchanged; the alpha.9 -> Beta 1 upgrade qualification exists to keep it that way.
