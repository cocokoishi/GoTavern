# GoTavern v0.1.0-alpha.11

A prerelease of the alpha line. `v0.1.0-alpha.9` remains the STABLE release: `releases/latest`, the bare
`install.sh` / `install.ps1` and Docker `:latest` still serve it. Get this build explicitly:
`install.sh --version v0.1.0-alpha.11` (Windows `install.ps1 -Version v0.1.0-alpha.11`), or
`docker pull ghcr.io/cocokoishi/gotavern:v0.1.0-alpha.11`. The channel rule lives in one script,
`scripts/classify-version-tag.sh`, shared by the release workflow, the Docker workflow and both installers.

alpha.11 is the release where the remaining P1 evidence gaps were moved from prose to **measured
capabilities**, and where three real product defects found by those new gates were fixed. It is still a
prerelease: the compatibility matrix keeps 18 PARTIAL rows, and the honest remaining gaps are listed in
`docs/gap-sweep.md` and in this note.

## What changed since v0.1.0-alpha.10

### A Node-originated stock tree, and Node -> Go -> Node -> Go

`tools/build-node-stock-tree.mjs` boots the pinned Node server and drives its **own** endpoints (23 API
operations) to create a second user, non-default settings with unknown keys, characters with real PNG avatars
and alternate greetings, chats with swipes and chat variables, a group and group chat, a world book, a complex
preset, Quick Replies, a theme, a persona avatar, a background and thumbnails. Only three items are seeded, each
labelled with the reason pinned's API cannot express it. The tree is hashed (raw + normalised over a declared
volatile set, with the declaration itself verified) and `tools/qualify-node-stock-tree.mjs` runs the full round
trip: Node writes -> Go reads -> Go mutates -> restart -> mutate -> pinned Node reads and continues -> Go reads
again, asserting state and whole-tree preservation (194 assertions). The gate found a real defect: repeated
multipart text fields were replaced instead of accumulated like multer, now fixed in `internal/server/characters.go`.

### Group chats: the provider request is measured, not assumed

`tests/browser/group-chat-probe.mjs` drives the unmodified pinned frontend on both subjects over one
deterministic tree and `compare-group-chat-legs.mjs` compares the exact provider request bytes for 15
scenarios plus restart/reload: 2 and 3 characters, a disabled member, natural/list/manual activation, auto
mode, previous-speaker ban, group greeting, character+chat+global world info, Author's Note at depth,
samplers/stops, continue, swipe, regenerate, impersonate and truncation. 240 guards, 26 discriminating checks,
`match`; the comparator proves it can fail (order swap, dropped prompt, changed role, missing case,
non-discriminating knob) and the pinned oracle re-records byte-identically.

### Preset semantics: 18 A/B knob pairs

A single catalogue emits 36 provider-wire scenarios (purely additive: 222 -> 258 fixtures) for 18 preset
knobs, 14 of them discriminating and 4 measured-noop, and proves the four relations: Node(A)==Go(A),
Node(B)==Go(B), Node(A)!=Node(B), Go(A)!=Go(B). `docs/preset-semantics.md` inventories 46 preset fields as
implemented / measured-noop / explicitly unmeasured. Four executed Go mutations (ordering, stop value, strict
default, reasoning arm) each turn a named subtest red; no Go divergence was found, so no Go prompt code changed.

### 酒馆助手 second-order state

A two-subject browser differential covers variables by scope (chat/character/global/preset), persistence across
reload/restart/chat/character/preset switches and helper on/off, preset mutation reaching the next generation,
real event ordering and state-at-event, and a closed iframe -> bridge -> host -> disk -> next-request loop driven
from an in-iframe script. 30 named guards; five mutations prove the gate can fail. Recorded findings include
character-scope not surviving reload on **either** subject (equivalence observation) and a documented settle step
for pinned's debounced metadata flush; the render path and rendered-message URLs remain explicitly unproven.

### Real provider/proxy canary, and the remote-embeddings decision

`scripts/live-provider-proxy-canary.mjs` + `.github/workflows/live-provider-canary.yml` drive the shipped binary
through the production client to a real provider and a real configured HTTP proxy, default-safe: with no
credential the run reports `SKIPPED` (never a pass) and with `--require-credentials` it fails instead. Local
no-credential reachability already proves TLS/DNS/response parsing and that a configured proxy is honoured
(refused CONNECT) rather than bypassed; credentialed completion/streaming/cancel runs need a maintainer secret.
Remote embedding providers are now a **declared exclusion** rather than a vague 500: each provider-backed source
answers HTTP 501 naming the source, the reason and `docs/remote-embeddings-decision.md`, and the decision is
carried in `GOAL.md` and the matrix.

### Character imports: CharX, BYAF and RisuAI are implemented

All three formats are now implemented and replayed against a pinned oracle that records the pinned route's
response bytes **and the whole stored user tree** for 19 scenarios including malformed/truncated/wrong-bytes/
oversized archives (`TestPinnedNodeCharactersImport`, 34 subtests). The uploaded-avatar crop is probed
(512x768 want_resize cover-not-stretch by sampled geometry; no Jimp pixel equality claim). A browser
New Character -> stored PNG -> export read-back probe with tamper teeth exists (`--self-test` 5/5, caught:true).
Remaining: AVIF/APNG avatar re-encoding is a pure-Go decoder boundary, Jimp-exact pixels are not claimed, and the
browser probe is not yet wired into a CI workflow.

### Data safety: crash-atomic chat writes, Windows reads, bounded upload memory

`/api/chats/rename` was copy-then-unlink (pinned's shape); a kill between the two left **both** chat files. It is
now one `os.Rename` under the user-content lock with the mtime refresh `/api/chats/recent` needs. The crash
matrix is deterministic at 9 named fault points plus 115 seeded random hard kills across save/append/swipe/
regenerate/branch/metadata/delete/import/group-save, with every post-crash state verified after restart and the
pre-fix defect reproduced as a mutation. The last two bare Windows node-persist reads now retry the transient
sharing violation narrowly. Multipart uploads are bounded and spooled: the same 200 MiB sprite upload dropped peak
RSS from 552.0 MB to 37.7 MB (14.6x) with identical stored bytes; the deliberate limits are documented as
user-visible boundaries.

### Surface and configuration

All 37 previously-registered-missing legacy redirect aliases are implemented (50/50) with the pinned 308
semantics — including three that were answering 302 — proven against a 111-case pinned recording, and
`/api/tokenizers/remote/textgenerationwebui/encode` exists with a 31-case pinned differential. Configuration
parity is now enumerated and gated: 116 pinned default keys (75 implemented, 14 explicit-no-op-with-warning,
2 explicit-unsupported, 25 inherited) plus 31 CLI options; silent ignores became bounded startup warnings.

### Qualification and harness fixes found by the new gates

The new gates found and fixed their own defects on first Linux execution, each recorded in the commit history:
a group-chat fixture compared the *checkout's* git identity instead of pinned behaviour; the node-stock-tree
workflow wrote the generator report somewhere the qualifier did not look; and the determinism digest kept the
count of volatile files even though the pinned server itself decides how many settings backups exist.

## Compatibility state

Matrix: **PASS 3 / PARTIAL 18 / FAIL 0 / NOT_APPLICABLE 1**, P0 0. Every remaining PARTIAL and its user impact is
in `docs/gap-sweep.md`; the P1s that remain are: the packaged drop-in gate still uses a derived input tree (the
Node-originated capability exists but is not wired into that gate), chat crash evidence is Windows CI only while
chat backup is unimplemented, the helper render path/rendered URLs are unproven, tokenization on a stock tree
without a tokenizer directory is unproven, the live provider canary has no credentialed run recorded, and the
frontend-owned world-info/preset long tail plus preset-varying group chats remain unmeasured. No status was
promoted without executed evidence and no severity was lowered to improve a number.

## Persistence and upgrades

On-disk format is unchanged (SillyTavern's own). The release qualification downloads the **published**
`v0.1.0-alpha.10`, verifies its published checksum, installs it with the real installer, boots it over the
generated corpus, upgrades the same tree to this release, continues the same chat, restarts, restores the backup
and boots alpha.10 again; a fresh install and a SillyTavern-data-copy drop-in cover the other arrival paths.

## Performance

The required `GoTavern smoke metrics` gate re-runs the paired benchmark (pinned Node vs GoTavern, same runner,
alternating rounds) plus a ten-minute soak at the released commit; its run id is in the qualification table
appended to this release body. The README's performance table quotes the paired measurement of the alpha.10
code line (the release commit adds documentation only), so the numbers and the gate that re-measured them remain
separately checkable. Absolute numbers move with the runner; the ratio is the claim, and the compatibility gates
run on the same commit so "faster" cannot mean "assembled a different prompt".

## Install

Linux/macOS: `curl -fsSL https://raw.githubusercontent.com/cocokoishi/GoTavern/main/install.sh | sh` installs the
STABLE alpha.9 (no version argument). For this prerelease:
`sh install.sh --version v0.1.0-alpha.11`. Windows: `.\install.ps1` (stable) or
`.\install.ps1 -Version v0.1.0-alpha.11`. Docker: `ghcr.io/cocokoishi/gotavern:v0.1.0-alpha.11`. The release ships
six canonical archives (linux/darwin/windows x amd64/arm64) plus `checksums.txt`; both installers verify the
published digests before installing. Runtime-qualified in CI: linux/amd64 and windows/amd64; the other four are
built and structurally inspected.

## Qualification

Published only if every required workflow is green **at the tag's commit**: GoTavern CI (verify, race,
browser-evidence, full oracle sweep), whole-session differential, world-info slot ordering, drop-in qualification
(with the packaged Q21 hand-back), Browser differential (full mode), release qualification (including the
published alpha.10 upgrade and cross-baseline rollback), smoke metrics and the Docker image build. The same-SHA
gate refuses a narrowed push run, and the published body appends the machine-generated evidence table.

## Known limitations

- The packaged drop-in gate still uses a DERIVED stock tree; the Node-originated tree is proven by its own gate
  but not yet wired into the packaged/release path.
- Chat crash evidence is Windows CI only (no Linux `-tags gotavern_faults` job); chat backup is unimplemented.
- 酒馆助手 render path and rendered-message DOM URLs are unproven; character-scope variables do not survive reload
  on either subject.
- FTB/AVIF/APNG avatar re-encoding is a pure-Go decoder boundary; Jimp byte equality is never claimed.
- Remote embedding providers are an explicit exclusion (HTTP 501 with the reason); local in-process ONNX ML and
  arbitrary Node server plugins remain out of scope.
- A credentialed live provider/proxy run has not been recorded; the canary exists and defaults to SKIPPED.
- World-info long-tail preset fields, text-completion instruct/context consumption and preset-varying group
  chats remain unmeasured; tokenization on a stock tree without a tokenizer directory is unproven.
- Non-amd64/non-x86 runtimes are built and inspected, not executed; Windows arm64 is tested through the CI
  Windows jobs where the runner permits.
- Inherited upstream weaknesses are reproduced on purpose (parity over "safer but different"); each is recorded
  in the matrix.

## Breaking changes

None known. `config.yaml` keys, CLI, ports, directory layout, installer syntax, Docker volume semantics and API
response shapes are unchanged; the alpha.10 -> alpha.11 upgrade qualification exists to keep it that way.
