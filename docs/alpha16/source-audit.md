## 1. Method, and what "coverage" means here

The audit has two coverage tiers, and this file states both so neither is mistaken for the other.

1. **Mechanical coverage** — every owned Go file is parsed by `tools/alpha16-graph` with `go/parser`:
   603 files total, **296 production**, 307 test, 40 packages, 260 package-level variables, 64
   internal import edges, 331 production call/decl facts. The tool records imports, declarations,
   package state, sync fields, goroutines, timers, child processes, context detachment, filesystem
   mutations, HTTP calls and lock/atomic call sites. **This tier proves every file was seen; it does not
   prove any file was understood.**
2. **Deep coverage** — a lane read the file for a named question, and every claim carries `file:line`
   (checked by the assembler). Five lanes produced **72 hypotheses** (5 `confirmed-defect`, 37
   `verified-risk`, 15 `untested-hypothesis`, 13 `intentional-parity`, 2 `out-of-scope`), **67 writer
   rows**, **19 startup-mutation rows**, **66 concurrency entries**, **33 cache rows**, **45
   request-path stages**, **20 gate rows** and **13 harness groups**.

The computed census of the 296 production files (`ownership-map.json` → `coverage`), after the M0b pass:

| level | count |
|---|---|
| named by a lane (filesInspected, any depth) | 236 |
| — of those deep-read | 106 |
| — of those mechanical only | 130 |
| cited in a lane report but not in `filesInspected` (e.g. a converter named in Lane D's registry table) | 39 |
| not named by any lane | 21 |
| — OS-specific sibling files (`*_unix.go`, `*_windows.go`, `*_bsd.go`, …) whose shared implementation is named | 17 |
| — developer tooling under `tools/`, `tests/`, `cmd/`, `upstream/` | 4 |
| — **product logic not individually named** | **0** |

**The honest statement:** every one of the 296 production files is mechanically covered by the generated
graph, **all 61 product-logic files the v1 census could not name are now named** (M0b, shared task-8: 22
route families, each recorded as implemented / inherited-pinned / declared-exclusion / gap, with "covered, no
finding" where true), 106 files are deep-read, and the remaining 21 unnamed files are OS-specific siblings of
named files and developer tooling outside the product. The contract-critical owners were deep-read in v1:
every mutating route family the writer matrix covers, every synchronisation primitive, every cache, the whole
request path, the provider registry and the gate set.

**Tool caveat, measured by Lane C:** `source-graph.json` `facts[]` is a floor. It does not descend into
package-level `var` initializer func literals (3 of 7 timer sites are therefore absent) and does not count a
package-level var's type expression as a `sync-type` site (1 recorded vs 21 `sync.Mutex` sites found by the
lane's own census). `globals[]` is sound. The concurrency numbers in §4 come from that independent census,
not from the graph.

## 2. The request path

`docs/alpha16/audit/a-request-path.md` (26-stage graph, 19 map stages) and the Lead's 12-stage summary in
`lead.json`. The path: CLI parse (`cmd/gotavern/main.go`) → config resolution and config-init mutation
(`internal/commandline/paths.go`, `internal/configinit/config.go`) → boot locks and startup mutations
(`internal/app/server.go`, `internal/startup/data_startup.go`) → handler composition
(`HTTPHandlerOptionsFromCommandLine`, `internal/server/http.go:140-240`, ~60 flat fields) → pinned middleware
order (access log, CORS, host/basic auth, whitelist, CSRF/session, panic boundary) → explicit route-domain
table (`routes_registry.go`) → accountRuntime/session → handler → `startup.UpdateUserContentFile` or
`internal/outbound` → `httpx`/compression response.

Findings worth naming beyond the five: **A-H1** — there is no app-level body-parser stage, so account and
settings routes act on bodies pinned ignores and reject in a different order; **A-H2** — a falsy `cors.origin`
loses the Express automatic-OPTIONS answer (200 vs 404); **A-H3** — `settings/save` empty-body/error semantics
differ (Go 400/500 vs pinned 200 + `{}`); **A-H5** — with CSRF disabled and accounts off, login can answer 500
where pinned answers 200; **A-H13** — the `/proxy/:url(*)` route is missing (see §7, L-H4).

## 3. Persistence, writers, startup mutations

`docs/alpha16/audit/b-persistence-writers.md` + 67 writer rows in the map. **37 of 56** audited writer rows use
the data-root flock plus `atomicReplace`/`atomicCreate` end-to-end; the exceptions are classified rather than
assumed (`no lock` is never equated with `not atomic`). 19 startup mutations carry their pinned basis; the
config file, cookie secret, node-persist default user, directory template, legacy data migration, seeding,
disk cache, settings backup and auto-update-OFF paths are all enumerated.

- **B-H3** (five-strongest #4): `gotavern migrate --force` sets aside only `config.yaml` and `data/`
  (`internal/migrate/migrate.go:432-436`); pre-existing `certs/` and the third-party overlay are copied over in
  place (`:221-230`) → silent overwrite of destination user data.
- **B-H4**: the recursive destructive routes (`/api/users/reset-step2`, `characters/delete` with
  `delete_chats`, delete-user) run outside the shared content lock; a crash/concurrency probe decides whether
  it is observable or pinned parity.
- **B-H5 intentional parity**: `/api/characters/create` returns 200 with no card when the write fails, because
  pinned swallows the same error — recorded so it is not "fixed" into a divergence.
- **B-H1/B-H2**: config-init and legacy-migration console output is silent/one-line where pinned prints what it
  changed and offers a countdown; the owner decision (GOAL §15.5 quiet-by-default vs AGENTS rule 13) is
  recorded as a question, not silently resolved.

**Node ↔ Go ↔ Node state, stated honestly:** the committed runtime round-trip fixture plus the zero-diff
CI re-record and the `GoTavern Node stock tree round trip` release artefact prove round-trip/idempotence for
the covered paths. **GOAL §14 items 2 (full byte census of a real tree) and 4 (rollback byte equality on the
real tree) are NOT met** and are not claimed.

## 4. Concurrency, lifecycle and caches

`docs/alpha16/audit/c-concurrency-lifecycle.md`. Independently counted over 270 production Go files
(`internal/`+`cmd/`, non-test): `sync.Mutex` **21** (13 struct fields, 8 package-level), `sync.RWMutex` 0,
`sync.Map`/`Cond` 0, `sync.Once` 2, `WaitGroup` 1, `Pool` 1, `atomic.*` 9 code sites, `go` statements 12,
timers 7 (`AfterFunc` 1, `NewTicker` 1, `NewTimer` 5), `exec.Command` 3, `context.Background()` 20 —
each classified. 15 cache rows carry the GOAL §15.3 fields.

- **C-H6** (reliability runner-up, strength 4): the only **unbounded** wait in the normal lifecycle —
  `heartbeat.stop()` waits on the writer mutex (held across fsync) and `<-writer.done` outside the `Close`
  context (`internal/app/heartbeat.go:77-85,127`, called at `internal/app/server.go:431-433`).
- **C-H1**: login/recover/reset and basic-auth rate-limit windows never evict a key; pinned's
  `RateLimiterMemory` deletes each key on a per-key timeout — the only unbounded map that **diverges** from
  pinned, with a cheap failing test.
- **C-H2 intentional parity**: `settingsSaveMu` serialises saves across disk I/O, but pinned's save is
  synchronous on the event loop, so Go serialises *less*. This is recorded **before** any per-user coordinator
  is designed — the plan's R2 candidate currently lacks a red test.
- **C-H8**: the `-race` job omits `internal/app` and `internal/lockacquire`, and the real signal path has no
  test.
- Caches: all three identity-keyed caches document key/value/owner/lifetime/eviction/invalidation/rebuild/
  fallback and state a same-size+same-mtime residual window; the residual is pinned by tests, not hidden.
  No cache is an implicit second database.

## 5. Providers, transport and config

`docs/alpha16/audit/d-providers-startup.md`. 26 pinned chat sources; **24 registry rows + the MINIMAX
route-level branch = 25 implemented**, COMETAPI is an explicit 501 with zero outbound; 258 provider-wire
scenario inputs replay on every `go test ./...`; tokenizer exactness has three exact engines plus an explicitly
marked guesstimate fallback. All 63 `HTTPHandlerOptions` fields are tabled; 12 chat-path config keys bypass the
options struct and are re-read from disk at request time.

**Three options with no Go counterpart were found, and they are the top three findings:**
`claude.enableAdaptiveThinking` (no reader at all), `gemini.apiVersion` (chat path hardcodes `v1beta` while
media/TTS read it), `gemini.enableSystemPromptCache` (declared no-op — correctly). Also: `--configPath` is
ignored by the chat-path config readers; `SILLYTAVERN_REQUESTOVERRIDES` works as a config value but not as the
JSON env override; redirect credential stripping is per-initial-request where pinned is per-hop; OpenRouter's
Claude prompt-cache transform is absent and undeclared; the tokenizer cache write is non-atomic where pinned
writes atomically. The M0b pass added **D-H18** (verified-risk, persisted-bytes): `POST /api/stats/update`
rewrites `stats.json` through a Go map (sorted member order) and writes immediately, while pinned keeps the
parsed object in memory, sets `timestamp` in place preserving insertion order, and flushes only every five
minutes or on exit — values and unknown members survive, so the divergence is member order plus write timing,
and the code's own header comment says the route is not implemented. The pass also recorded four **stale
documentation claims** (not fixed in M0): `translate.go` says google/bing "cannot be pinned" where AGENTS
boundary 4 makes ownership, not pinnability, the objection; `stats.go`'s header says update/recreate are not
implemented while they are; four `api-inventory.md` search rows say requestOverrides is not applied while
`search_routes.go` applies it; and `claude_chat.go` still repeats the cache-key comment D-H6 contradicts.

## 8. Refactor candidates — dispositions, not a plan

The plan's R1–R6 are answered in `lead.json` → `refactorCandidates`, each with evidence-for, evidence-against
and a disposition:

| id | disposition | reason |
|---|---|---|
| R1 configuration composition | **DECLINE** | no measured defect in the default launch path; the translation is already one function with tested truthiness rules; nesting is not move-only. D-H1/D-H10 would justify a *bounded* fix, not a rewrite. |
| R2 runtime lifecycle | **HOLD** | the candidate's premises are being killed by the oracle: settings-save serialisation is parity-or-better (C-H2), detached backup timers are parity (C-H5), Git child-kill is parity (Lane C). C-H6 (unbounded shutdown wait) is the only actionable part and is a bounded fix. |
| R3 persistence consistency | **HOLD** | 37/56 writers already use the shared core; the atomic-write core is do-not-rewrite. The actionable parts are B-H3 and B-H4, both bounded fixes. |
| R4 extension execution | **DECLINE** | detached Git is pinned parity (simple-git has the same 5-minute block timeout and no abort). Request-scoping would be safer-but-different and needs a product decision. |
| R5 cache framework | **DECLINE** | three caches with different measured eviction reasons and pinned residual windows; merging them creates the generic abstraction the plan forbids. |
| R6 domain split | **DECLINE (M0b closed the census with no measured seam)** | no measured coupling defect was produced; file count is not evidence; the ordered-JSON extraction is already refused with a measurement. |

No M4 refactor is selected in M0. The plan's rule — at most one boundary at a time, only with evidence — is
satisfied by selecting none.
