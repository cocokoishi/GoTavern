# GoTavern v0.1.0-alpha.20 — the source-audit and performance release

`v0.1.0-alpha.20` is the release in which the compatibility work is driven by **reading the real production
code** rather than only by test suites: seven defects found by source audit are fixed with reproducers, the two
compatibility gaps alpha.18/19 recorded as unimplemented (the pinned `chat_metadata.integrity` guard and the
group-save auto-backup) are closed, the JSON hot path is rewritten to serialize with one buffer (measured
allocation reductions of 47.8%–81.1%), and the product page is shortened to a real landing page with a rebuilt,
honest performance figure. The pinned baseline is unchanged — SillyTavern `1.19.0` at `06bde939` — and the
fourteen required release gates all run at one commit.

## What changed

**Seven source-audit fixes, each with a real reproducer and a RED→GREEN record.**

- **The SD/text-completion socket-close interrupt fired after every completed request.** Go cancels the request
  context when the handler returns, so a bare watcher fired the pinned cancel *after a success*; A1111's
  interrupt then aborts a running generation (possibly another tab's). Pinned guards with
  `!response.writableEnded`; one watcher type now publishes "response ended" before returning, and the control
  test proves a genuine mid-flight disconnect still interrupts.
- **Character avatar mutations never invalidated the cached thumbnail.** Pinned unlinks it on `POST /edit`
  (only when a file was uploaded), `edit-avatar` and `delete`; GoTavern invalidated only on import, so after
  replacing a character's picture the list, chat avatars and group collages kept showing the OLD image, and
  delete-then-recreate showed the deleted character's face. The three pinned call sites are implemented.
- **The card base64 decoder rejected payloads pinned reads.** Pinned's `Buffer.from(text, 'base64')` skips all
  non-alphabet bytes, accepts URL-safe `-`/`_`, stops at the first `=`, drops a lone leftover character and
  replaces invalid UTF-8; Go's strict decoder rejected those cards (a URL-safe card was readable by pinned and
  unreadable by GoTavern). The pinned leniency is implemented, with the Node runtime as the oracle.
- **Provider redirects followed 19 hops where node-fetch follows 20.** node-fetch's `counter >= follow` rejects
  the 21st redirect; Go's `via` length is the equivalent bound, and the transport was one short. A chain of
  exactly 20 now succeeds, the 21st is refused.
- **`sanitize-filename` replacement mode diverged.** The BYAF import path uses the replacement form: the npm
  package's two-pass semantics replace the reserved-name match (so `CON` becomes `_`, not an empty name),
  include `0` in the `COM`/`LPT` class, and trim a trailing dot/space before replacement. Stored filenames now
  match pinned for names such as `Aria `, `CON`, `NUL.tar.gz` and `COM0`.
- **`chat_metadata.integrity` was not enforced on chat save.** Pinned refuses a stale overwrite with
  `400 {"error":"integrity"}` unless `body.force` is truthy; the whole pass/fail table is implemented
  (missing/empty/legacy files pass, an unparseable first line fails, BOM stripped, strict `===`, JavaScript
  truthiness for `force`, config read once at boot).
- **Group saves never scheduled the pinned auto-backup.** Pinned's `/api/chats/group/save` goes through the same
  `trySaveChat`, so it schedules the same throttled `chat_<key>_<timestamp>.jsonl` backup; both save routes now
  share the handler's one boot-time backup manager.

**Performance, measured on the same host and input, with a byte-identity gate.**

`marshalOrderedNodeJSON` recursively allocated a fresh `bytes.Buffer` per object/array plus a `[]byte` per
string and copied every nested result into its parent. The serializer now appends into ONE buffer (optional
size hint may only pre-size). Server-only benchmark, before → after: `/api/worldinfo/get` 4 MiB
35,351,980 → 18,472,490 B/op (−47.8%) and 69,648 → 28,690 allocs/op (−58.8%); `/api/chats/get` 2,000 messages
6,325,000 → 2,997,031 B/op (−52.6%) and 42,015 → 16,015 allocs (−61.9%); with the size hint the world arm is
6,683,886 B/op and the chat arm 2,022,448. A frozen golden generated by the pre-change code (15 documents ×
4 hints, covering member order, every C0 control, U+2028/29, astral runes, invalid UTF-8, surrogates, `-0`,
`1e21`, `1e-7`, top-level scalars, 4-level nesting and deliberately wrong hints) replays byte-identically. A
same-binary A/A self-test reproduced the allocation columns within 0.003%. Process-level ABBA: `chat-get`
p50 43.57 → 33.31 ms (−23.5%, separable); `world-get` latency, boot time and peak RSS are **NOT SEPARABLE**
on this 2-vCPU host and are reported as such.

**Product experience.**

The README's first screen shrank from 11,170 to 3,714 characters (−66.8% under the release gate's own boundary
definition) into a product-homepage shape: one-line positioning, one figure, three features, 30-second install
for both operating systems, compatibility/limits summary and documentation links; methodology and gate
evidence moved into `docs/`. The performance figure was rebuilt as hand-authored dark+light SVG from the
validated artifacts (colour-blind-safe pair, larger type, honest zero-based per-row axes) and is gated by a new
headless 36-check script (XML syntax, 360/720/1200 px containment, 13 px type floor, alt/desc value
consistency, GitHub-Markdown wrapper). The compatibility matrix records the two closed gaps and the decisions
that keep the remaining disclosed differences.

## Compatibility and platform

The SillyTavern baseline (`1.19.0`, commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`) and the compatibility
contract are unchanged. The fourteen required gates are the same fourteen as alpha.19 — no gate was added,
removed, renamed, skipped or weakened — and they all ran at this release's commit. An alpha.19 data directory
continues to work unchanged; the new checks only refuse what pinned refuses.

## Known limitations

- **`GOAL.md` §14 remains NOT MET.** No real, long-used user directory has been qualified; the private
  channel's disposition is `PRIVATE_NOT_RUN`. Everything this release claims is synthetic/agent-generated.
- **darwin/arm64 runtime is NOT runtime-qualified**: the archive is built and archive-inspected, not executed
  on this host, and the macOS arm64 extension lifecycle is UNVERIFIED. **windows/arm64 is build-only.**
- **The performance rows are Layer A local evidence** (Windows arm64, 2 vCPU, co-tenant load recorded in
  `docs/alpha20/perf/profiles/HOST-AND-LOAD.md`); the release-cited performance claim remains the same-SHA
  Linux `GoTavern smoke metrics` gate, and peak RSS is one paired local row, not a gate.
- **The 60-minute soak cannot prove absence of a leak.** It reports RSS/heap/goroutine/FD/CPU/p95/p99/error and
  data-integrity trends over a mixed workload; `UNPROVEN` is the verdict for "no leak", not a green check.
- **Not executed:** a real-provider latency row, p99 on the real UI corpus journey, and a >8-user concurrency
  row (the local harness drives 8 accounts only; 16/32-user rows were not run). `-race` runs on Linux CI only.
- **Kept disclosed differences:** Brotli response negotiation (decoded bytes identical on all probed resources;
  a `br`-only client receives identity from GoTavern; a new pure-Go dependency plus outbound decoder outranks
  the benefit, decision D-02); the pinned `_cache/characters` read/write cache is not implemented (verify-only
  parity; derived cache, no user byte, decision D-03); the `dominantColor` row-average differs from Jimp's
  decode by ±1 per channel on 7 of 24 JPEGs (named normalisation, disclosed exclusion); pinned's
  `console.error` diagnostics for the integrity/backup branches are not reproduced.
- The oracle keeps its 26 named normalisations and 6 not-compared surfaces, each with its evidence; no
  comparator was widened in this release.
