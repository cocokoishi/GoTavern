# GoTavern v0.1.0-alpha.16 — the synthetic adversarial qualification release

`v0.1.0-alpha.16` closes the alpha.16 programme (M0-M6) and keeps the same SillyTavern 1.19.0 baseline and
the same compatibility contract as alpha.15. It does not add a user-facing feature. It adds a **synthetic
adversarial qualification**: an audited code and behaviour inventory, a deterministic scenario factory, a
real-browser E03+E04 combined journey driven through the unmodified pinned frontend, recorded-oracle
discrimination for two provider-config defects, evidence-based refusal of six proposed refactor boundaries,
same-input performance and soak evidence in both directions, and release rails that read the embedded
evidence document inside each required artifact.

The strongest claim this release makes is the synthetic one, with its scope stated. `GOAL.md` section 14 —
a real, long-used user tree qualifying the drop-in claim — is **NOT MET** at this release and is not claimed
by any sentence here. See Known limitations.

### Defects fixed in this programme

Each was reproduced before the fix, and each fix landed with the gate that now sees it.

- **D-H3 — `claude.enableAdaptiveThinking` was unread by the chat path**, so a shipped `false` still sent the
  adaptive payload. Fix commit `60454bc` (35 changed lines in `internal/server/claude_chat.go`). Red-first
  test `TestChatCompletionClaudeAdaptiveThinkingFollowsTheConfig` failed four subtests before the fix; the
  discriminating pair is committed in the provider-wire fixture from `dbd32aa`/`fa5385f`.
- **D-H2 — `gemini.apiVersion` was unread by the MakerSuite generate and status URL builders.** Fix commit
  `1a7b914` (21 changed lines in `internal/server/google_chat.go`). Red-first test
  `TestGoogleChatAPIVersionFollowsTheConfig` failed with the `/v1beta/` path where pinned uses `/v1/`; the
  recorded scenarios cover both generate and status.
- **B-H3 — `migrate --force` did not move the destination `certs/` directory and the extension overlay into
  the backup**, so a forced migration could replace them without a recovery copy. Fix commit `7f91192`
  (32 changed lines in `internal/migrate/migrate.go`): the replaced-path set is every path the run replaces,
  and a dry run prints the same set. Red-first tests failed with destination bytes replaced and no backup.
- **L-H1 — the committed benchmark baseline predated an accepted product change**, so the comparison failed
  for a stale-baseline reason rather than a regression. Fixes `05479fa` (a deliberate regeneration dispatch
  mode), `39cec62` (the regenerated baseline, recorded by `GoTavern bench profiles` run `42164978648`,
  completed/success) and `ef41eec` (the closure record, with the green comparison run `42165562517`,
  completed/success). The alpha.15 card-text cache win is inside that baseline.
- **Adversarial ratchet port race — a harness precondition was being reported as a product listener defect.**
  Fix commit `98400d6` (test-only). `GoTavern Lane CI` run `42162940621` (completed/failure) is the
  before-record and run `42163485576` (completed/success) the after-record.
- **M2 harness defects, disclosed because they change how the journey is driven** (all harness-side, none a
  product finding): a preset selected but not applied to the live prompt manager, a save race read as a
  16-byte difference, a leg-abort that hid the other legs, an import dialog targeted at the wrong element, a
  send-blocking overlay, and a branch-metadata persistence order. Each fix commit is listed above; the run
  that exposed it is cited beside it.

### Harness and disclosure decisions

- **An installed prompt-replacing extension is configured off through its own setting, not uninstalled.** The
  E03+E04 journey detects the takeover, disables it through the extension's published setting, and records
  detection, disable and intactness. This is a harness decision about a shared 22-extension environment, not a
  product claim about that extension.
- **Startup overlays are dismissed through their own close controls**, one at a time, and an overlay without a
  dismiss affordance is named and refused rather than removed by DOM surgery.
- **The user turn is attributed to its streaming normal generation**, not to the quiet-generation request some
  extensions issue at startup, so a quiet-generation request can no longer be mistaken for the measured turn.
- **The group turn is quiesced before it is persisted and read, and branch metadata is persisted before the
  reload**, so both comparisons are deterministic.
- **The tier ladder is narrowed on purpose.** Fast is 12 blocks and 3 extensions, medium is 60 and 10, full is
  120 and 22 with all three books staged. Only full is release-admissible; branch and qualification dispatches
  use the narrower tiers and never support a full-coverage claim. Push runs keep the legacy `profile=none`
  journey byte-identically.

## Performance

All figures below are from downloaded artifacts; the artifact is the record. Absolute values are
runner-relative and comparable only within the same runner image label and version.

- **In-process scale, large JSONL and provider assembly — `GoTavern bench profiles` run `42200357353`
  (completed/success), artifact `bench-profiles`, against the committed baseline recorded at `05479fa`.**
  The artifact's `verdict.txt` says `comparison: passed`, `failures: 0`, and all 31 benchmarks are PASS
  (`comparison.txt`). Meaningful improvements: `BenchmarkStaticPageLoad` -10.8%,
  `BenchmarkChatCompletionAssemble/scaled_1MB` -6.8%, `BenchmarkChatCompletionMarshal/scaled_1MB` -3.7%,
  `BenchmarkCharactersAllScale/cards_1000_32KB_image` -3.7%, `BenchmarkScriptJSCompressed` -3.2% (B/op -1.6%),
  `BenchmarkWorldInfoList/worlds_1000_x_8KB` -3.2%, `BenchmarkChatSummary/chats_1000_x_16KB` -3.1%,
  `BenchmarkCharactersAllScale/cards_100_128KB_image` -2.9%, `BenchmarkCharactersAllScale/cards_10000_4KB_image`
  -2.4%. Regressions: `BenchmarkFrontendIndex` +0.7%, `BenchmarkFrontendAsset` +0.5%,
  `BenchmarkChatCompletionAssemble/largest_recorded` +0.2%, `BenchmarkManyFrontendAssets` +0.1%; the largest
  allocation movement is `BenchmarkPageLoadGzip` B/op +2.2%. Every movement is inside the ratified two-sided
  tolerances (ns/op 60%, B/op 15%, allocs/op 15%), so this is a same-work comparison, not a redefinition; a
  speedup beyond those bands would itself fail.
- **Cold and warm boot, request latency and fresh-install footprint — `GoTavern smoke metrics` run
  `42200361137` (completed/success), artifact `smoke-metrics`, against the M0 record `GoTavern smoke metrics`
  run `42160114658` (completed/success).** Both sides ran on `ubuntu26` image version `20261101.186.1`, the
  same kernel, 4 vCPU and the same binary size. Cold start to the pinned version record improved from
  **917.25 ms to 273.59 ms** and cold start to listener from **898.95 ms to 192.02 ms**; warm start improved
  from **29.22 ms to 26.91 ms**. Reported in the other direction: `/version` p50 went from 0.611 ms to
  0.768 ms (+25.7%), `GET /` p50 from 6.457 ms to 7.964 ms (+23.3%), and warm-boot RSS from 18.31 MB to
  19.32 MB (+5.5%). The fresh-install seed is identical on both sides (203 files, 16,169,121 bytes) and the
  install staging footprint is identical (27 files, 98,910,141 bytes, warm-minus-cold delta zero). The smoke
  gate asserts structural properties only, not performance, so these latency movements are reported, not
  graded; p99 is not collected by this harness.
- **8-user concurrent writes — `M5 measurements` run `42212715040` (completed/success), artifact
  `m5-eight-users-evidence`.** This is the row's BEFORE record: 8 accounts, 6 waves, 144 operations,
  `errorRate` 0, throughput 287.425 operations per second over a 501 ms measured wall, 5,627 ms of account
  provisioning outside the measured waves, and a 221 ms harness-measured boot to auth-aware readiness. Per-route
  p50/p95/p99: settings save 58.871/65.346/66.956 ms, settings get 28.440/38.928/39.367 ms, chat save
  37.299/87.728/100.784 ms. Every account saw its own marker and no other account's. No latency threshold was
  asserted: the first run of a row has no noise estimate, and the AFTER run at a change under test is what
  would apply the previous p95 x 1.25 ceiling. The AFTER does not exist yet (Known limitations).
- **30-60 minute soak — `M5 measurements` runs `42209244735` and `42226780977` (both completed/failure under
  the retired statistic), artifacts `m5-soak-evidence`.** Two real 45-minute runs of the same row reported
  old least-squares slopes of +39.8 B/s and +885.1 B/s, which was the **methodology defect**: the slope over
  the last third of a GC sawtooth is dominated by which GC phase the window boundary samples land in. Both
  artifacts' per-third statistics are flat. Run `42226780977` per-third means are 43.84, 45.24 and 43.97 MB
  and per-third minima 34.25, 34.87 and 34.40 MB; the third mean is lower than the second, the floor is flat
  and the overall drift is negative (-6.09 MB). Run `42209244735` has the same shape (means 44.67, 44.76 and
  45.57 MB; minima 34.71, 33.13 and 33.57 MB; drift -8.47 MB). Commit `9f6a76e` replaced the fail-closed
  statistic with two checks a GC phase cannot move: the last-third mean must not exceed 1.10x the larger of the
  previous two third means, and the last-third GC floor must not exceed the first-third floor plus 4 MiB, with
  all three third statistics and the old slope recorded in the verdict. Both real artifacts pass the corrected
  rule, a synthetic monotonically rising series fails it by name, and a synthetic perfectly flat sawtooth
  passes it while the retired slope would have failed that flat series (+2,217 B/s). The correction is a
  removal of a phase-aliased statistic, not a widening of a threshold that was catching real growth. The soak
  row is **not** one of the 13 required release gates, its same-commit ratification has **not** been done and
  the real-leak question is **UNPROVEN** (Known limitations).

## Compatibility

The pinned SillyTavern 1.19.0 baseline, `default/**` fresh-install contract, the unmodified pinned frontend and
the provider-wire compatibility contract are unchanged. This release makes no data-schema change and no
user-data migration. The 13 required same-SHA gates in `docs/release-manifest.json` are unchanged in number
and strengthened in content: the combination-journey gate now reads embedded release evidence, and the soak
gate's correction is confined to the measurement row. The publish path runs the fail-closed verifier before
the release is created, refuses a run whose required event, job, artifact or embedded evidence does not match
the candidate, and appends the same-commit evidence table to the published body.

## Known limitations

Every skipped or UNPROVEN scenario is listed here; none is implied to be covered.

- **`GOAL.md` section 14 — the real private-tree drop-in claim — is NOT MET.** The private channel's
  disposition this round is `PRIVATE_NOT_RUN` (no authorised original on the qualification host). This release
  claims a synthetic adversarial qualification with the scope described above, not universal drop-in proof,
  and no sentence here should be read as the stronger claim.
- **Streaming-cancellation performance is UNPROVEN.** Cancellation has functional gates, but no
  time-to-first-byte, inter-frame or cancel-to-idle metric exists, and no performance harness drives it.
- **Real provider-relay p99 under load is UNPROVEN.** The performance rows are in-process assembly and
  marshal; a real relay through the outbound transport under concurrency is not measured.
- **The 20-extension page-load row has no gate and no baseline.** The extension-overhead harness is
  descriptive; it asserts nothing and is not a performance gate.
- **The 8-user AFTER run has not been made.** The BEFORE record exists; the change-under-test run with the
  previous per-route p95 as its ceiling is the next row, and no 8-user latency number is graded until then.
- **The soak row's same-commit ratification has not been done.** The two real 45-minute runs are at different
  candidate commits and support the corrected tolerance but do not ratify it by the plan's same-commit
  procedure. The **real-leak question is UNPROVEN**: the corrected rule is a detection floor, so a leak slower
  than a 10% mean rise or a 4 MiB floor rise over 45 minutes would pass by design.
- **Smoke-metrics p99 is NOT collected.** The harness records median, p95, max and mean; p99 for the version
  route and the shell route is UNPROVEN on both sides of the comparison.
- **macOS ARM64 remains a runner blocker, with a recorded downgrade.** The `darwin/arm64` archive is built and
  archive-inspected but is **NOT executed**: this repository's runner platform answers that the arm64 macOS
  runner configuration is unsupported and cancels the job, as recorded at alpha.15 after three attempts. The
  publish job depends on that execution job, so on this platform the publish job does not run; alpha.15 was
  published by running the release workflow's own programs against that run's artifacts, and the release body
  recorded the consequence. The downgrade is transparent and there is no `continue-on-error` loophole; the
  darwin/arm64 target is NOT runtime-qualified.
- **`windows/arm64` remains BUILD-ONLY**: no hosted runner of that architecture exists, and the boundary job
  asserts that limitation instead of implying execution.
- **Extension takeover and quiet-generation decisions are harness decisions, not product claims.** Configuring
  an installed orchestrator off through its own setting, dismissing startup overlays through their own controls
  and attributing a turn to its streaming normal generation are how the shared 22-extension environment is made
  measurable; they do not assert extension behaviour beyond what the recorded requests and persisted state show.
- **Fast and medium tiers are narrowed.** Their greens cover 12/3 and 60/10 ingredients against the full tier's
  120/22 and cannot support a full-coverage or release-admissibility claim.
- **Page-init egress hermeticity is OPEN.** Some browser page initialisation reaches the live network; the
  decision to stage it away or to record an explicit allowlist has not been made, so the journey's page-init
  egress is not hermetic.
- **The committed benchmark baseline has no cold-guard row**, and no statistical comparison is used: the
  figures are medians over a small number of rounds, so sub-percent deltas are noise and are not claimed as
  wins.
- **The real user's card and preset prose are not in this repository.** The journeys use committed
  derivations and synthetic generators; a real user's card and preset never enter the tree or an artifact.
- **Narrowed oracle dispatches are not the full oracle.** A probe that did not run is unverified, not
  verified-equal; only the full-sweep dispatch exercises the whole provider-wire corpus.
