| **Lane** | A (production source audit) |

## Summary

Pinned SillyTavern registers its stable-diffusion / text-completion cancel side effect on the TCP
socket's `close` event, and guards it with `!response.writableEnded`:

```js
// src/endpoints/stable-diffusion.js:316-321 (/api/sd/generate)
request.socket.removeAllListeners('close');
request.socket.on('close', function () {
    if (!response.writableEnded) {
        const interruptUrl = new URL(request.body.url);
        interruptUrl.pathname = '/sdapi/v1/interrupt';
        fetch(interruptUrl, { method: 'POST', headers: { 'Authorization': getBasicAuthHeader(request.body.auth) } });
    }
    controller.abort();
});
```

(same shape at `src/endpoints/stable-diffusion.js:568-576` for `/api/sd/comfy/generate` with `&& !item`
and `:682-690` for `/api/sd/comfyrunpod/generate` with `/cancel/<jobId>`, and
`src/endpoints/backends/text-completions.js:288-296` for the koboldcpp abort with
`!response.writableEnded`.)

GoTavern ported that handler as a goroutine on `request.Context().Done()`. That is not equivalent:
net/http cancels the request context **when `ServeHTTP` returns** — from the `http.Request.Context`
documentation, "For incoming server requests, the context is canceled when the client's connection
closes, the request is canceled (with HTTP/2), or when the ServeHTTP method returns." So after a
perfectly normal, fully written response the watcher fires the interrupt/abort too. The pinned guard
suppresses exactly that case, and no GoTavern handler had an equivalent of `writableEnded`.

## Node oracle / pinned behaviour

`tests/oracle/sillytavern-1.19.0-sd-generate.json` records **exactly two outbound requests** for every
successful `/api/sd/generate` scenario (`generateForgeKeepsModules`, `generateNonForgeUnsetsModules`,
`generateOptionsNonOkKeepsModules`, `generateOptionsThrowsKeepsModules`, `generateNonOk`, `generateThrows`):
`GET <mock>/sdapi/v1/options`, `POST <mock>/sdapi/v1/txt2img` — no interrupt. The comfy fixture's failure
scenarios record one or two outbound requests and no interrupt either (`comfyPromptFailed: outbound=1`,
`comfyHistoryFailed: outbound=2`).

The `!response.writableEnded` guard is also visible in the pinned source quoted above; a socket-close
event that fires after the response ended runs the handler with the guard false, and a close event that
already fired before the listener was registered is not replayed by Node's EventEmitter.

## User impact

1. A1111/Forge: after **every** successful `/api/sd/generate`, GoTavern POSTs `/sdapi/v1/interrupt` to the
   image backend — a request pinned never makes. A1111's interrupt cancels the currently running
   generation, so a finished request in one tab (or the user's next queued generation, or another user of
   the same backend) can be aborted by an earlier request's completion. It also adds permanent noise to
   the backend's own log and breaks provider-wire equality on this route.
2. Comfy / RunPod / koboldcpp: the same stray request on error/handler-exit paths; it was intermittent
   there only because the pre-existing `finished` channel sometimes won the scheduler race, which is why
   the suite and the alpha.19 oracle never saw it.

## Fix

New `internal/server/socket_close_watcher.go`:

- `watchPinnedSocketClose(request, onClose)` arms one goroutine that selects on the context and a
  `finished` channel, and returns a watcher whose `end()` publishes "the response has ended" (the Go
  form of `writableEnded`) and releases the goroutine.
- Handlers call `defer watcher.end()`. Because net/http cancels the request context only after
  `ServeHTTP` returns (and after the defers), a cancellation observed with the flag set can only be the
  end of a completed response, so the pinned side effect is skipped; a real mid-flight disconnect leaves
  the flag false and the interrupt still runs.
- A context with a nil `Done()` (e.g. `context.Background`) arms nothing — the exact alpha.19
  goroutine-leak class — and an already-cancelled context arms nothing, because Node does not replay a
  close event to a listener registered afterwards.

All four sites now use it, with their pinned conditions preserved (`!item` for comfy/RunPod,
koboldcpp-only for the text-completion abort).

## The rewritten existing test (why this is a strengthening, not a weakening)

`internal/server/sd_generate_test.go::TestSDA1111InterruptOnClientClose` was changed in the same commit.
The old body was:

```go
ctx, cancel := context.WithCancel(context.Background())
cancel()
...
request := httptest.NewRequest(...).WithContext(ctx)
handler.ServeHTTP(recorder, request)
select { case <-interrupted: ... case <-time.After(5*time.Second): t.Fatalf(...) }
```

Why that encoded a wrong precondition:

1. It cancelled the context **before the handler ran**, i.e. it simulated a socket that had already
   closed. Node's `EventEmitter` does not replay `'close'` to a listener registered after the event, and
   a caller already gone has no generation in flight to interrupt — pinned's `!response.writableEnded`
   guard is about a response that was *not* written, which requires the handler to have been running.
2. `httptest.NewRecorder()` never cancels the request context, so the test needed the manual
   pre-cancellation to trigger anything at all — and that made the assertion depend on goroutine
   scheduling rather than on the product contract.

The new body drives the real trigger and is strictly stronger: a real `httptest.NewServer`, a provider
that holds `POST /sdapi/v1/txt2img` open (`sawTxt2Img` barrier), a client cancellation **while the
request is in flight**, and the interrupt then required on the peer. It keeps the test's name and its
stated purpose (a caller that goes away produces the interrupt) and removes the recorder blind spot that
let A20-A survive the suite.
