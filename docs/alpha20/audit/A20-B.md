## Summary

`internal/userdata.SanitizeFilename` is the port of the pinned dependency `sanitize-filename` (see
`src/util.js:621-625` `sanitizeSafeCharacterReplacements`). The alpha.19 implementation was a
**one-pass** reading of the package. The pinned package is a five-replacement pipeline followed, when a
replacement is supplied, by a **second sanitization with an empty replacement**:

```js
// SillyTavern/node_modules/sanitize-filename/index.js
var illegalRe = /[\/\?<>\\:\*\|"]/g;
var controlRe = /[\x00-\x1f\x80-\x9f]/g;
var reservedRe = /^\.+$/;
var windowsReservedRe = /^(con|prn|aux|nul|com[0-9]|lpt[0-9])(\..*)?$/i;
var windowsTrailingRe = /[\. ]+$/;

function sanitize(input, replacement) {
  var sanitized = input
    .replace(illegalRe, replacement)
    .replace(controlRe, replacement)
    .replace(reservedRe, replacement)        // WHOLE match -> replacement
    .replace(windowsReservedRe, replacement) // WHOLE match -> replacement
    .replace(windowsTrailingRe, replacement) // whole trailing run -> ONE replacement
  return truncate(sanitized, 255);
}
module.exports = function (input, options) {
  var replacement = (options && options.replacement) || '';
  var output = sanitize(input, replacement);
  if (replacement === '') { return output; }
  return sanitize(output, '');
};
```

Two consequences the one-pass port got wrong:

1. **Replacement mode is not "remove":** a reserved name (`CON`, `con.txt`, `NUL.tar.gz`, `COM1.png`,
   `...`) becomes **one replacement character**, and a trailing run (`a. `, `a `, `name. . `) becomes the
   base text plus **one** replacement — not an empty/trimmed string.
2. **`com[0-9]`/`lpt[0-9]` include ZERO**, so `com0`/`lpt0` are reserved; the port required `1-9`.

## User impact

Replacement mode is on the **BYAF card import** path:
`internal/server/characters_import_formats.go:1231` (stored PNG name), `:1306` (imported chat name),
`:1338` (alt-image base name). A card whose name ends in a space or dot (`"Aria "`, `"Dr. Smith. "`) or
is a reserved device name (`CON`, `NUL.tar.gz`, `COM0`) was stored under a different filename than pinned
would choose. Consequences: the character's file/folder name differs from pinned's on the same tree, the
GoTavern tree handed back to Node does not have the file name Node derives from the card, and a card
named `COM0…` escapes the reserved-name rule entirely (on Windows a device-name path cannot be created).
No user byte is lost; this is a data-layout/parity divergence.

## Fix

`internal/userdata/userdata.go` now implements the pinned algorithm exactly:

- one `sanitizeFilenamePass(input, replacement)` performs the five replacements **in order**, each
  reserved/trailing rule replacing the whole match with ONE replacement string, then truncates to 255
  UTF-8 bytes on a code-point boundary;
- `SanitizeFilename` runs pass 1 with the caller's replacement and, when it is non-empty, pass 2 with
  `""` — the pinned exported function;
- the reserved class is `com0-9` / `lpt0-9`.

`SanitizeUserFilename` in `internal/server`/`internal/startup` is untouched; plain-mode output is
unchanged except the two intended device-#0 corrections (`com0*`, `lpt0*`).

The pre-existing `internal/userdata/userdata_test.go` table encoded the **wrong** pinned expectation in
four replacement-mode rows (`"..."`, `"con.txt"`, `"COM1"`, `"name. . "` expected `""`/`"name"`). Those
rows were corrected to the measured oracle values with a comment naming the measurement; the test was not
deleted or loosened (it still asserts exact strings, and the new oracle table is stricter and larger).
