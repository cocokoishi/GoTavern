## Measurement first (as instructed), then the finding

The alpha.19 layer-B finding recorded the general class — "every Express JSON GET route gets conditional
304 for free; GoTavern's other JSON writers still do not" — and fixed four call sites
(`/api/extensions/discover`, `/api/data-maid/view`, `/api/sprites/get`, `/api/users/me`). Alpha.20's
question was whether the class still has a surface after those four. The measurement is an enumeration of
the GET surface in this server, not a mass change:

| GET route | body | Express 304 possible? | GoTavern before this change |
|---|---|---|---|
| `/api/extensions/discover` | ordered JSON | yes | 304 (alpha.19) |
| `/api/data-maid/view` | file bytes | yes | 304 (alpha.19) |
| `/api/sprites/get` | file bytes | yes | 304 (alpha.19) |
| `/api/users/me` | ordered JSON | yes | 304 (alpha.19) |
| `/csrf-token` | JSON with a FRESH random token every request | **no** — the ETag differs on every request, so `req.fresh` is never true; pinned also answers 200 | 200 (correct) |
| `/version` | JSON, constant body, weak ETag | **yes** | **200 (divergence)** |
| `/login`, `/callback`, `/callback/` | redirect/HTML | n/a (no ETag route) | n/a |
| static assets | files | yes (send's own conditional path) | implemented, separate from the JSON writers |

There is no other GET JSON writer: `grep -n 'GET /api' internal/server` finds exactly the four fixed
routes plus `/api/data-maid/view`, and the frontend's page load issues no other GET `/api` request
(`docs/frontend-startup-calls.md`; the rest of the SPA's data loads are POSTs). **So the "general class"
is now measured as one route, not a large surface**, and the earlier `partial` label can be narrowed to
"complete for the GET surface this server exposes" once this lands.

## Finding

Pinned's route is `app.get('/version', async (_, response) => { const data = await getVersion();
response.send(data); })` (src/server-main.js:272-275). `res.send(object)` is the same Express send path
whose 304 face was measured with a raw socket for `/api/extensions/discover`
(`docs/alpha19/findings/layer-b-conditional-get.md`): weak ETag, and a fresh conditional GET/HEAD gets
304 with the ETag preserved and NO representation headers. The pinned frontend fetches `/version` on
every page load (`public/script.js:504`), so a reload after the browser has cached the response sends
`If-None-Match`; pinned answers 304 with no bytes, GoTavern re-sent the whole JSON body with 200.

GoTavern's `serveVersion` set the JSON `Content-Type`/`Content-Length`/weak `ETag` by hand and never
looked at `If-None-Match` — every other header was already the pinned one, which is why no fixture caught
it (all of them request unconditionally).

## Reproducer

`internal/server/a20_version_conditional_test.go::TestA20VersionAnswersPinnedExpressFreshness`:

- GET `/version` → 200 with a weak ETag (recorded);
- GET + the matching weak tag → **304**, ETag preserved, no `Content-Type`, no `Content-Length`, empty body;
- GET + the strong form of the tag (`"…"`, no `W/`) → 304;
- HEAD + the tag → 304 (Proxy/Express serve HEAD from the GET route);
- unmatched tag → 200 with the body; tag + `Cache-Control: no-cache` → 200 with the body.

RED (before the fix):

```
a20_version_conditional_test.go:75: GET + If-None-Match = 200, want 304 (pinned res.send answers the measured 304 face)
a20_version_conditional_test.go:75: GET + If-None-Match = 200, want 304
a20_version_conditional_test.go:75: HEAD + If-None-Match = 200, want 304
--- FAIL: TestA20VersionAnswersPinnedExpressFreshness
```

GREEN after: all five subtests PASS; `TestPinnedNodeAccountsEnabledLoginAndSessionContract` and
`TestPinnedNodeCORSMiddleware` (the suites that assert `/version`'s body/content-type and the CORS/Vary
behaviour) stay green.

## Node oracle

Not a fresh pinned probe: the mechanism is the pinned Express `res.send` path, whose exact 304 face was
already measured against the pinned server with a raw socket in the alpha.19 layer-B finding (same
`res.send`, same freshness rules: `If-None-Match` token list with weak/strong equivalence, `*`, and the
`Cache-Control: no-cache` refusal). The route's *content* is separately fixture-pinned by the accounts
oracle; this change changes no body byte and no non-conditional response header.

## User impact

On a page reload the browser revalidates `/version`; pinned answers 304 (no body), GoTavern re-sent the
~200-byte JSON each time. No user-visible wrongness — this is the same wire/cache-parity class as the
four alpha.19 routes, on the last browser-requested GET. It also keeps the compat claim honest: after
this, every GET route this server exposes that CAN be fresh answers the pinned 304 face.

## Fix

`serveVersion` now ends in `httpx.WriteJSONBytesConditional(w, r, http.StatusOK, body)` — the shared
helper alpha.19 introduced, so the weak ETag, the Content-Type/Length set, and the measured 304 face are
identical to the other four routes by construction. HEAD is handled by the same helper (`IsFresh` accepts
GET/HEAD; net/http suppresses the body for HEAD).

## Regression guard

`internal/server/a20_version_conditional_test.go` pins the whole conditional face (weak form, strong form,
HEAD, non-matching, `no-cache`) plus the absence of representation headers on the 304. It cannot pass
vacuously: the unmatched-tag and `no-cache` rows prove the route still serves the representation when it
must.
