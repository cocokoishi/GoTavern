## Why a template exists

A cold pinned boot on this host spends ~114 s compiling the frontend libraries (Webpack) before it listens;
every probe that needs a FRESH data root would otherwise pay that again. The template is produced by booting
the READ-ONLY pinned checkout ONCE over an EMPTY scratch directory and letting the pinned product seed it. No
file is copied from the pinned checkout by hand and no file is invented: the tree is exactly what a first-run
pinned server writes.

The template contains: the pinned default-user seed (characters, lorebooks, presets, themes, quick replies,
backgrounds, avatars, instruct/context/sysprompt sets), `_cache` directories, `_storage`, `cookie-secret.txt`,
the generated `config.yaml`, and a warm `_webpack` cache (so a probe boot over a copy compiles in ~9–40 s
instead of ~114 s).

## What it is used for

Every alpha.20 pinned probe (a/b/c/d), the differential (both legs), and the fault-injection probe start from
a copy of this template via `freshDataRoot()` and record the template census digest in their own evidence, so
a reader can tell exactly what tree a probe started from.

## What it does NOT claim

- It is one host's cold boot: file mtimes differ between hosts and are not part of the digest (bytes are
  hashed), but `settings.json` timestamps may differ across two independent cold boots. The digest is a
  statement about the tree this run produced, not a cross-host constant.
- It is not the pinned `default/**` assets (those are the pinned checkout); it is the seeded data root a user's
  first run creates.
- It is not a user's long-lived directory (`GOAL.md` §14 stays NOT MET).
