# alpha.20 change record — the ordered-JSON single-buffer serializer

**Status: IMPLEMENTED, byte-identical, allocation win measured; one merged hotspot (the Lead's sequencing rule).**
This file is the evidence record for the one product change the perf lane made this round. It is Layer A
(Windows arm64, 2 vCPU, shared with the other alpha.20 lanes); the release performance claim remains the Linux
`GoTavern smoke metrics` paired gate. Nothing here is a CI verdict.

## 1. What changed (and what it cost)

`marshalOrderedNodeJSON` used to build the JSON with `bytes.Buffer` recursion: a fresh buffer for **every**
object/array, and `marshalNodeJSONString` allocated a fresh `[]byte` for **every** member key and string value,
then the parent copied the child's bytes in. On a 4 MiB world book that is a buffer tree, not a serialization.

The change replaces it with `orderedJSONWriter`, one append buffer that grows by doubling, with:

- `appendCharacterJSONString`, the append-based form of the pinned `writeCharacterJSONString` encoding (same
  control/quote/backslash escapes, raw U+2028/U+2029, invalid UTF-8 → U+FFFD, astral runes copied) — the
  original writer is untouched and the golden test cross-checks the two;
- `appendECMAScriptNumber`, the append-based form of the pinned number formatting;
- `marshalOrderedNodeJSONHint(value, hint)`: the hint pre-sizes the one buffer. The world-info route passes the
  world file's on-disk byte length (`readWorldInfoRouteFile` now returns it) because the response is the
  `JSON.stringify` of that file; a wrong or zero hint can only change the number of grows.

**Cost stated:** ~+180 lines in `internal/server/image_metadata_index.go`, no new cache, no retained state, no
change to what is stored or returned, no new dependency, binary size unchanged to the page (`gotavern.exe`
60,880,384 B before and after this change on this host, measured by file size). The size hint is pure capacity.

**Files:** `internal/server/image_metadata_index.go` (serializer + escaper + hint), `internal/server/worldinfo.go`
(hint threading only), NEW `internal/server/a20_perf_bench_test.go`, NEW
`internal/server/a20_marshal_byte_identity_test.go`, NEW `internal/server/testdata/a20-ordered-json-golden.jsonl`.
No existing test file was edited.

## 2. Byte-identity gate (the Lead's condition 1)

The golden file was generated by the **pre-change** code (`git show 7d1178e:internal/server/image_metadata_index.go`,
run `-test.run TestA20GenerateGolden`, generator deleted afterwards, never committed) and frozen: each line is
`{name, kind, inputB64|textB64, outputB64}`. The committed test replays it and refuses to pass vacuously
(fewer than 20 records is a failure; it asserts both kinds were exercised).

| corpus | records | what it covers |
|---|---:|---|
| documents | 15 | member order incl. integer-like keys, nested objects/arrays, empty containers, unicode/U+2028/U+2029, escapes and all C0 controls, lone + paired UTF-16 surrogates, -0/1e21/1e-7/large integers, top-level string/number/bool/null, 4-level nesting, invalid UTF-8 bytes, `__proto__` member |
| strings | 9 | empty, quotes/backslash, controls, CJK/emoji/combining, line separators, invalid UTF-8, lone surrogate as invalid UTF-8 |

`TestA20OrderedJSONMarshalByteIdentity`: **PASS** — 15 documents × 4 hints (0, 1, exact+7, 1<<20) + 9 strings,
every byte equal to the frozen output; the hinted and unhinted serializers also agree with each other, and the
new escaper's bytes are cross-checked against the untouched `writeCharacterJSONString`. A wrong hint is a
required case, so "a hint can never change content" is demonstrated, not asserted.

## 3. Same-host before/after (server-only benchmark, `-benchmem`)

Two binaries, same host, same benchmark file: `server-before.test.exe` sha256
`973E92C7121D7DFC626EA2A7B657A4B454B4EB8E3E486851341ECEE5AC51E578`, `server-after3.test.exe` sha256
`553F309DA47F4489AC6BFFEC4BF1DDC85007A89E40D0DC657164FD6252185059` (the after binary also carries the
hint-assisted arms). Order alternated before → after → before → after; 5 rounds per arm per binary in the final
pair. Allocation columns are deterministic; **ns/op is NOT SEPARABLE on this host** (see §4).

| arm | before B/op | after B/op | delta | before allocs/op | after allocs/op | delta |
|---|---:|---:|---:|---:|---:|---:|
| `BenchmarkA20MarshalWorld4MB` (unhinted — the paired row) | 35,351,980 | **18,472,490** | **−47.8%** | 69,648 | **28,690** | **−58.8%** |

The benchmark documents are shaped like the measured endpoints (a 4 MiB world with 1,024 nested entry objects;
a 2,000-message chat), and the A/A self-test row is the two before runs: 35,351,980 vs 35,352,928 B/op (world)
and 6,325,000 vs 6,325,096 B/op (chat), i.e. a spread of 0.003%/0.002% — the paired allocation claim is far above
the harness's own noise. The chunked buffer's `bytes.growSlice` share of the world window (§1.2 of
[`hotspots.md`](hotspots.md)) is what this removes.

## 4. What is NOT claimed

- **ns/op improvement: NOT SEPARABLE.** The before binary's own rounds on identical input spanned 269-1,473 ms
  (world) and 144-357 ms (chat); the after rounds spanned 259-425 ms and 98-137 ms. The direction is favourable
  but the host's co-tenant spread is larger than the effect, so no speed multiplier is claimed. Allocation
  volume is the claim.
- **Peak RSS: not measured at this layer.** A marshal buffer is transient; the process-level RSS effect (if any)
  is the ABBA window's row and is reported there, not extrapolated from B/op.
- **Characters-all 10,000-card row: NOT SEPARABLE by this change.** That route builds its JSON in
  `characters_json.go` (alpha.18's direct writer), not through `marshalOrderedNodeJSON`, so its 403.1 MB/op is
  unchanged — as the Lead's condition 4 requires, it is reported as unchanged rather than force-fitted.
- **Process-level endpoint latency/RSS** is measured separately in the quiet-window ABBA; this file gains that
  row only when the artifact exists.

## 6. Regression list

No allocation regression on either measured arm; the two hinted arms are candidate-only and both beat the before
rows. The one measured intermediate regression is recorded rather than hidden: reserving the 6x worst-case
escape size per string made the first hinted chat prototype 3.89 MB/op (worse than the unhinted 2.99 MB/op) by
over-reserving near the end of a pre-sized buffer; the shipped version reserves the plain size and measures
2.02 MB/op. No output/order/Unicode/provider-wire change shipped.
