## 4. Resource trends and the leak verdict

Per-boot segments (RSS decimal MB; each restart is a new process with an empty heap, so per-segment only, never
pooled):

| segment | boot | RSS start | RSS end | peak | slope |
|---|---:|---:|---:|---:|---:|
| 0 (cold) | 191 ms | 69.38 | 89.88 | 119.16 | −0.15 MB/min |
| 1 | 191 ms | 22.54 | 85.43 | 118.20 | +1.58 MB/min |
| 2 | 161 ms | 22.39 | 95.69 | 115.97 | +2.02 MB/min |
| 3 | 132 ms | 22.30 | 85.05 | **119.51** | +2.26 MB/min |
| 4 | 131 ms | 22.21 | 91.96 | 116.86 | +1.98 MB/min |
| 5 | 131 ms | 22.39 | 89.78 | 119.45 | +1.31 MB/min |

CPU over the hour: **user 691.4 s + system 392.1 s**.

Interpretation, bounded: every segment warms from a fresh ~22 MB process to a ~85-96 MB working set with a
per-segment peak stable at **116.0-119.5 MB**; the restart resets it. That is consistent with per-boot warm-up
(card-text cache, response buffers, GC arenas) rather than unbounded growth — but **a 60-minute RSS trend is not
a leak proof**: the harness's own verdict is `leakVerdict: UNPROVEN` and it stays UNPROVEN. Heap, goroutines and
file descriptors are **not observable** from outside this binary (no pprof endpoint; Windows `procstat` reports
`handles=null`); graceful-shutdown flush and same-port restarts are not measured (forced Windows stop; fresh port
per boot).

## 6. Honest limits

- **No leak proof.** 60 minutes is a trend; the verdict is UNPROVEN and cannot be upgraded from RSS.
- **No heap/goroutine/FD census** (not externally observable without changing the binary).
- **No graceful-shutdown claim** (forced Windows stop).
- **Generation/SSE-cancel unexecuted** for the recorded 502 reason; a provider relay soak needs a permitted
  controlled peer and is not this run.
- **Latency rows are loopback, two harnesses share 2 cores, sample counts are printed beside every percentile** —
  none is an SLO.
- **One host, one platform**; Linux/macOS rows are CI gates, not this document.
- The earlier `7a8f977` run is superseded and is not cited here; the final candidate's two CI-found fixes
  (HEAD `/version` body; SD in-flight-disconnect race) are in this subject.
