# Pinned startup inventory

Baseline: SillyTavern `1.19.0`, commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`.

This order follows the pinned startup call path. It is an implementation checklist, not evidence that GoTavern already matches it. A `partial` item names its tested surface; all other side effects remain unimplemented until exercised against isolated Node and Go runtime roots.

`src/server-init.js` is a separate pre-start helper that calls `addMissingConfigValues(process.cwd()/config.yaml)` and catches errors. It is not the main `server.js` entry path; the command-line parser calls `initConfig` directly.

## Server initialization chain

Before the promise chain below runs, `server-main.js` constructs the Express middleware stack. In particular, `cookieSession(...)` calls `getCookieSecret(DATA_ROOT)` while the module is being evaluated; this reads a non-empty `cookie-secret.txt`, migrates a legacy config secret, or generates and writes a new secret. Multer also creates `DATA_ROOT/_uploads`. `internal/startup.InitializeDataStartup` reproduces these data effects and the ordered pre-listener data chain through statistics initialization. `internal/app.Start` now connects command-line parsing, data startup, protocol selection, the HTTP handler, IPv6-first IPv6-only and IPv4 listeners, TLS loading, and graceful listener shutdown. `internal/server.NewHTTPHandlerWithOptions` matches the captured fresh-start routes, cookie-session signing, CSRF-token persistence, account login, IP-whitelist response, global/per-user Basic Auth, and host-whitelist validation/scan behavior. The IP whitelist page is captured before data seeding, matching middleware construction order; host-whitelist errors read the seeded/custom page when each request is denied. Password-protected login edge cases, recovery, account management, and most shared middleware remain incomplete.

After binding, `postSetupTasks` optionally opens the browser, writes an immediate `heartbeat.json` and timer when enabled, prints listen URLs, sets logging/title, and emits `SERVER_STARTED`. GoTavern prints the listen/browser URLs and handles signal-driven HTTP shutdown, but automatic browser launch, heartbeat work, stats flushing, the title/event, and cleanup are not implemented. Global and per-user Basic Auth plus enabled host validation are compared against the pinned Node server; the IP whitelist middleware is partially implemented and compared with the fresh-start Node response.

## Reference probes still required

- Empty, current, and legacy runtime snapshots before and after the full chain.
- Config file bytes, key migration precedence, backups, secrets, directory contents, default-content index state, and timestamps where observable.
- Failure injection for permission errors, malformed config/data, listener conflicts, and partially completed upstream migrations.
- Equivalent observations from a Go startup before any compatibility claim.
