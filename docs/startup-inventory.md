# Pinned startup inventory

Baseline: SillyTavern `1.19.0`, commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`.

This order follows the pinned startup call path. It is an implementation checklist, not evidence that GoTavern already matches it. A `partial` item names its tested surface; all other side effects remain unimplemented until exercised against isolated Node and Go runtime roots.

## Entry and configuration

| Order | Pinned operation | Observable behavior / follow-up | Source | GoTavern status |
|---:|---|---|---|---|
| 1 | `server.js` constructs `CommandLineParser` and parses arguments | Resolves standalone/global config and data paths; applies CLI/config values; may create the global config parent and data root; calls `initConfig` before server import. | [server.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/server.js), [src/command-line.js](https://github.com/SillyTavern/SillyTavern/blob/06bde939fb1e9c4c8d8641d810f0a916b5bce127/src/command-line.js) | not implemented |

`src/server-init.js` is a separate pre-start helper that calls `addMissingConfigValues(process.cwd()/config.yaml)` and catches errors. It is not the main `server.js` entry path; the command-line parser calls `initConfig` directly.

## Server initialization chain

Before the promise chain below runs, `server-main.js` constructs the Express middleware stack. In particular, `cookieSession(...)` calls `getCookieSecret(DATA_ROOT)` while the module is being evaluated; this reads a non-empty `cookie-secret.txt`, migrates a legacy config secret, or generates and writes a new secret. The pinned `server-main.js` then chains these operations in order before binding HTTP listeners:

After binding, `postSetupTasks` optionally opens the browser, writes an immediate `heartbeat.json` and timer when enabled, prints listen URLs, sets logging/title, and emits `SERVER_STARTED`. Graceful shutdown flushes stats, runs excluded plugin cleanup when present, disposes the character disk cache, restores the title, and exits.

## Reference probes still required

- Empty, current, and legacy runtime snapshots before and after the full chain.
- Config file bytes, key migration precedence, backups, secrets, directory contents, default-content index state, and timestamps where observable.
- Failure injection for permission errors, malformed config/data, listener conflicts, and partially completed upstream migrations.
- Equivalent observations from a Go startup before any compatibility claim.
