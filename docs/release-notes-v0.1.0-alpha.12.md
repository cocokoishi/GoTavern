# GoTavern v0.1.0-alpha.12

**This is the stable-channel release of the 0.1.0 line.** The tag keeps the historical `-alpha.12` spelling, but the
channel is `stable`: the GitHub Release is published without the prerelease flag, `releases/latest` points at it, the
bare `install.sh` / `install.ps1` fetch it, and the container image is tagged `latest`. `scripts/classify-version-tag.sh`
grows from one documented graduation (`v0.1.0-alpha.9`, preserved so that a re-run of that tag does not change the
channel of a published release) to a two-entry equality list, with regression cases pinning that alpha.10, alpha.11,
alpha.13 and every other version-shaped tag stay prereleases.

This release graduates the channel because, for the first time, the whole release shape is gated on one candidate
SHA: the packaged archive boots stock and Node-originated trees on Linux **and** Windows, the composed five-leg
journey matches pinned Node byte-for-byte per provider capture, the same-SHA required gates are enforced by
`scripts/verify-release-gates.mjs` before `gh release create`, and the archives built by this release are executed on
linux/arm64 (under QEMU) and on native macOS x86_64/arm64 runners before the publish job is allowed to run. The
same-SHA evidence table appended to this release body names the exact runs; nothing here replaces that table.

## What changed since v0.1.0-alpha.11

- **The combination journey is built and green in CI.** One composed session drives character × committed complex
  preset × 酒馆助手 × world info × variables × regex × Quick Reply × streaming × save/reload/swipe/regenerate/
  continue/group/restart/hand-back, on both subjects, and the comparator reports verdict `match`, 81 guards, 0
  failed, 0 asymmetries, every common provider capture byte-equal (`docs/combination-journey.md`). The earlier red it
  carried was three probe defects, not product divergence: a harness context cap that made a CJK-marker preset
  derivation exceed the token budget, restart-phase ordering, and drive-only preset signatures.
- **The packaged drop-in gate boots the Node-originated tree on Windows as well as Linux.** The account-enabled tree
  is shipped as a UTF-8 zip (Windows `tar.exe` decoded its CJK character filename in the OEM code page), verified
  against the Linux-recorded manifest before boot, booted through `Start.cmd`, and asserted for no undeclared writes
  and a crash-recovery restart (`docs/dropin-qualification.md`).
- **Cross-platform execution is a precondition of publishing.** `release.yml` executes the linux/arm64 archive under
  QEMU and both darwin archives on native macOS runners, and asserts the one remaining boundary (windows/arm64 has no
  hosted runner) instead of implying it (`docs/cross-platform-execution.md`).
- **Required gates now include the Combination journey and Helper state differential**, and the release manifest is
  enforced before publication, on `workflow_dispatch` runs at the tag commit only.
- **Chat-backup routes are recorded as implemented and replay-tested** (`/api/backups/chat/get`,
  `/delete`, `/download`); the stale "not implemented" claim was removed from the matrix, gap sweep and HANDOFF.

## Verification of this release

- The release body carries the same-SHA required-gate table generated by the publish job. Every named workflow must
  have a successful `workflow_dispatch` run whose `head_sha` is the commit this tag points at; a push-triggered run
  cannot satisfy the manifest.
- The published archives are additionally executed by the release workflow: linux/amd64 and windows/amd64 by the
  packaged drop-in and release-qualification gates; linux/arm64 under QEMU; darwin/amd64 and darwin/arm64 on native
  macOS runners.
- The post-publication smoke workflow downloads the published assets, verifies their checksums, unpacks them and boots
  against a stock tree.

## Known limitations

These are stated rather than implied; they are the same boundaries the compatibility matrix records.

- **windows/arm64 is built and structurally inspected, not executed.** No windows/arm64 hosted runner exists; the
  release workflow fails if that boundary ever stops being stated.
- **Remote embedding sources are a declared exclusion for this release.** Every provider-backed source answers an
  explicit 501 naming the reason (`docs/remote-embeddings-decision.md`); webllm/koboldcpp and caller-supplied vectors
  remain supported.
- **Local in-process ML is excluded by architecture** (`/api/extra/{caption,classify}`, `/api/speech/*`, local
  embeddings inside `/api/vector/*`): it would require an ONNX runtime, contradicting the static, no-extra-runtime
  distribution rule.
- **Arbitrary Node server plugins are excluded** and reported as such; the pinned frontend's extension ecosystem is
  otherwise first-class.
- **The Q7 background paint half is `partial`**: background files and tiles are served and render, but pixel-exact
  paint parity is not claimed (`docs/goal-scorecard.md`). Avatar/thumbnail/APNG/AVIF codecs are pure-Go and claim the
  observable contract, not Jimp byte equality.
- **No credentialed provider run is recorded in this repository.** The live canary exercises a real provider in its
  anonymous mode and records the provider's own decision; a credentialed end-to-end run is not claimed.
- **酒馆助手's rendering path and rendered DOM URLs remain unproven**; its state, variables, preset mutation and
  generation APIs are covered second-order by the helper-state differential and the combination journey.
- **Preset secondary features** (world-info secondary keys/recursion/probability/outlets/scan depth/budget,
  text-completion instruct/context template consumption, preset-varying group chats) remain narrowed rather than
  closed; the measured per-field server contract is documented in `docs/preset-semantics.md`.
- **Multi-user contention** (two users writing the same world/preset tree concurrently) is untested.
- **Inherited pinned behaviour is reproduced, not fixed** where a drop-in must match the oracle (for example the
  content-import host substring classification and the absence of a settings.json answering 500 on the backup/settings
  routes); these are recorded in the matrix rows rather than silently hardened.

## Artifacts

Six prebuilt archives are published, with `checksums.txt` beside them:

- `gotavern-linux-amd64.tar.gz`
- `gotavern-linux-arm64.tar.gz`
- `gotavern-darwin-amd64.tar.gz`
- `gotavern-darwin-arm64.tar.gz`
- `gotavern-windows-amd64.zip`
- `gotavern-windows-arm64.zip`

The container image is `ghcr.io/cocokoishi/gotavern:v0.1.0-alpha.12` (linux/amd64) with `latest` moved to it by this
stable release. Install by unpacking an archive and running `./start.sh` / `Start.cmd`, or through the bare
installers, which resolve `releases/latest`. No Go or Node is needed on the target host.
